# In-browser IFC validation (ADR 018)

buildingSMART's validation service, run in the browser: its own Python code
(IfcOpenShell, ifc-gherkin-rules, its header policy) on Pyodide, in a Web
Worker. The model never leaves the device.

`npm run validator:assets` (also run by `prebuild`/`predev`) assembles
`public/validator/` from the pins in `manifest.json` — downloads verified by
SHA-256 — and from this folder. The output is gitignored.

## Differences from the service, on purpose

- **ifcopenshell 0.8.5** (newest Pyodide build) where the service runs 0.8.6
  `8b5b400`. On the models checked so far the results are identical.
- **rtree and pyproj are stand-ins.** The pyproj one was compared with the real
  pyproj on all 7 013 EPSG codes and on the string forms pyproj accepts or
  refuses: identical.
- **No ClamAV, digital-signature or bSDD stage.** The file never leaves the
  device; signatures are checked by `lib/signing/`; bSDD would send the model's
  classification references to a third party (AGENTS.md §1).
- **Not shipped, though in the rules' requirements:** Django (+asgiref,
  sqlparse), pyspellchecker, pandas (+pytz), SQLAlchemy, sqlalchemy-utils,
  sqlite3, tabulate, python-dotenv — none is used outside production's database
  or the rules' own TESTING mode (61 → 37 MB). Checked: the full and the trimmed
  build give the same outcomes on three models, every stage (22 356 outcomes),
  but for Python memory addresses printed in some schema messages.
- **A fixed hash seed** (`PYTHONHASHSEED=0`): the rules print sets in messages
  and pick a rule's version from a set of tags, so with Python's random seed two
  runs of one model differ; fixed, they repeat.
- ifcopenshell is imported once when the driver loads, its import-time output
  discarded: without sqlite3 it prints "No SQL support", which inside a stage
  would read as a syntax error.
- Each rule's outcomes are reduced as production reduces them before saving
  (`reduce_db_outcomes` in `features/environment.py`): its warnings and errors,
  or one pass / not applicable. There is no per-rule cap.
